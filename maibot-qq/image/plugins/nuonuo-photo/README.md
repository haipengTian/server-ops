# 糯糯照片与通用绘图

在[糯糯生活照工作室](http://127.0.0.1:18011/extensions/haipengtian.nuonuo-photo/studio)生成并确认她的肖像，然后在 QQ 对她说：

> 发张你在咖啡店看书的生活照。

她会带着固定的原始肖像生成一张照片，通过当前聊天的图片发送通道发回来。包含糯糯本人的自拍、换装、与人或宠物合照都走这条路径。

也可以说“画只水彩小猫”“生成一张日落海报，写上周末愉快”。不含糯糯的内容走通用生图，不附带她的参考图，不强制改成摄影风格，也无需先设置肖像。两类请求共用已配置的图片接口和模型。

聊天模型选择工具后，插件使用现有 `utils` 模型根据原始消息和同一会话最近八条上下文确认语义及完整场景。合照不需要改说“照片”；有明确上下文的“换成夜景再来一张”也可理解。否定、引用、普通闲聊、索要表情包或检索已有图片不触发生图。识别失败时不提交图片接口。

`nuonuo_life_photo` 保留原入口，新增 `generate_image`；两者共用语义路由，即使上游选错入口也以实际请求为准。工作室中的生活照、通用绘图预览由管理员直接操作，不额外调用语义模型。

## 先确认形象

1. 在工作室点击“生成一张候选肖像”。会调用一次图片接口，预览完成后显示在左侧。
2. 喜欢这张脸后，点击“就用这个形象”。候选图只有经过这一步才成为固定参考。
3. 输入场景生成生活照预览，或到 QQ 明确要求自拍、生活照等。工作室预览不发到 QQ。

重新生成候选不会自动替换固定参考。生活照也不会反过来成为下一次生成的参考。相貌一致性取决于图片模型对参考图的遵循程度。

## 接口配置

插件配置页的“图片接口”提供地址、API Key 密码框和模型名。当前模型为 `gpt-image-2.5-flare`，使用 OpenAI 兼容的 `/v1/images/generations` 和带参考图的 `/v1/images/edits`，响应需要 `data[].b64_json`。

安装时通过已认证的原生 WebUI 接口沿用现有聊天服务地址和 Key，仅在本机保存；聊天服务日后换 Key 时，也需同步更新这里。插件不读宿主私有配置文件，不把 Key 传入聊天、模型提示或工具结果。

每个请求只生成一张，最多同时处理一个生成任务。两类工具按同一原始消息统一持久化去重。语义确认增加一次短文本模型调用；图片请求失败或超时不自动重试，上游可能仍已计费。生成后发送失败不会重新生图或自动重发。

## 查询进度与重新生成

可以问“刚才那张图生成好了吗”“为什么失败了”。聊天模型通过 `get_image_status` 查询当前聊天最近一次任务的真实状态、发送结果及失败原因，不调用收费图片接口。任务记录按聊天保存，其他会话不能查询这张图。

失败通知和已发送图片会同步进麦麦的思考上下文。通知发送失败时，状态工具仍能查到失败结果。接口的标准错误类别会转换成内容审核、参考图格式、参数、权限或限流等说明；不回显上游原文或认证信息。服务商没有提供可识别分类时，说明需要查看该服务的请求日志。

旧任务结束后，用新消息明确说“按刚才的场景重新生成一张”即可重新提交；同一条旧消息仍不会重复扣费。插件保留上一张场景，避免多轮催问后丢失重画对象。正在运行的任务不重复提交，超时也不自动重试；用户选择重画时，上游旧请求仍可能已经计费。

## 文件、状态和停用

服务器上的原始肖像、候选和生成图片保存在 `/opt/maibot-qq/runtime/data/plugins/haipengtian.nuonuo-photo`，状态在同目录 `state.json`。保留原件；页面只发送小预览图。生成后发送未确认时，可从这里取回已生成的 JPG。

代码在仓库 `maibot-qq/image/plugins/nuonuo-photo`，运行实例为 `/opt/maibot-qq/runtime/plugins/nuonuo-photo`。新参考图和图片接口 Key 属于实例私有数据，不进入代码仓库或公开镜像。替换参考图不会覆盖旧原件，之后生活照统一使用新参考，通用绘图不使用任何角色参考。

在插件管理中停用“糯糯生活照”即可关闭生图能力；停用不删除图片和状态。图片生成期间不要修改插件源码或重载插件，以免中断任务。中断的请求不会自动重试。
